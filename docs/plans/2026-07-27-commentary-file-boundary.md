# Commentary `file:` boundary and pre-submit validation

## Direction Brief

1. **Purpose** — Publish the user's existing two-game run unchanged and prevent a future public-commentary mismatch from entering the immutable community ledger before it can be published.
2. **Concept owner** — LaPlaceBench owns the commentary contract; submission and publication call the same public replay builder. The product independently enforces the identical consumer rule. Recorded model notes stay immutable evidence.
3. **Lifecycle and scope** — Replay verification happens before authentication. A read-only login lookup supplies the final `<login>--<run-id>` identity; exact public validation of every arena-eligible game then happens before permission lookup, fork, clone, copy, commit, push, or PR. The publisher repeats validation and atomically issues artifacts. Product production is updated first; then producer source regenerates the arena; finally one reviewed CLI version is published.
4. **Value hierarchy** — Immutable evidence > pre-irreversible fail-closed validation > producer/consumer parity > specific local feedback > current replay availability > speed.
5. **Adopted direction** — Allow `file:` only before whitespace or end-of-string and reject every non-whitespace continuation. Preserve other scheme/markup/scalar rules. Add a public-validation seam to submission, keep non-public runs outside that check, retain publisher defense in depth, and release only after consumer production verification.
6. **What disappears / is not protected** — Remove the separator-only exception and post-push-only discovery. Do not sanitize evidence, skip invalid eligible runs in the publisher, add fallback paths, or protect ambiguous `file:name` prose.

## Implementation

1. Replace the separator-dependent `file:` branch with a lookahead that rejects any non-whitespace continuation. Tests cover exact `back file: if ...`, terminal `file:`, `file:secret`, `file:C:secret`, `file:?q`, `file:#fragment`, `file:%2Fetc`, slash/backslash paths, and the existing unsafe set.
2. Add a narrowly named identity-aware submission helper. `buildPublicReplay` accepts an optional effective run ID used only to construct its `run_id`/filename bytes; normal publisher calls continue deriving the basename from the real directory. The helper enumerates game directories, reads recorded agents, skips `publicPair=null`, asserts the exact `<final-dir>/<game>` raw ref, and builds every eligible replay using the final submitted basename. It does not expose or print predicted digests.
3. Call replay verification, then the existing read-only login lookup, then exact final-identity validation before permission lookup or any fork/clone/copy/git action. On failure, print `公開リプレイ検証に失敗しました。提出しません` plus the original game/event/identity detail, return blocked, and emit no replay handoffs. Authentication failure remains unchanged because no final identity exists.
4. Preserve direct/PR lane behavior, non-public submissions, publisher atomicity, and the already-recorded run. Keep asynchronous validation for old clients and forged submissions.
5. After product production passes, bump the CLI to the next unused version, update lock metadata, run prepublish/pack/clean-install gates, publish once, verify registry identity/integrity, and record the release commit.

## Validation and rollout

- `npm run typecheck`; `npm test`; current-ledger generation and atomic writer tests.
- Focused submit tests: content failure with no external command; final-identity failure with only the read-only login call; zero permission/fork/clone/git calls after either block; unsafe eligible copy; baseline/self-match skip; direct/PR parity; no success URL. A local basename that passes but the prefixed final basename violates `raw_ref`/filename length must fail. Explicit-identity preflight bytes/digest must equal a build from a copy whose actual basename is the final identity.
- Product production first: both current refs and replay APIs return `200` before producer release.
- Push producer main: CI and publisher succeed, status is ready, both refs still return the expected games.
- Package: inspect dry-run/tarball files and digests, install into an empty temp project, smoke the CLI, publish once, verify `latest`, `gitHead`, integrity/shasum, and record without overwriting.

## Interrogation and rollback

Heavy implementation checkpoint must verify predicate parity, pre-mutation ordering, publisher-equivalent eligibility, unchanged evidence/digests, and product-first release identity. Before npm publication, revert is available; after publication, never overwrite/unpublish and fix forward in a new version. The current submitted run is never edited or deleted.
